# Artifact Services

**Path**: `internal/artifact/` — the module's code is everything in this folder and its transparent subfolders, excluding child module folders
**Parent**: repository root
**Submodules**: `archive`, `write`, `compare`, `provenance`, `nativeverify`

## Purpose

This module is the only owner of generated-output effects and observations. It validates complete plans, appends deterministic provenance, writes atomically, compares exact drift, and optionally runs safe declared native checks.

## Functional Responsibilities

- Validate paths, collisions, case-fold conflicts, reserved names, and executable intent for the complete plan.
- Preserve planned executable metadata through provenance, write, and comparison.
- Keep compiler provenance outside target-native package roots.
- Run native verification only for current output and only from adapter-declared official offline non-mutating checks.

## Subdomain Classification

**Supporting.** Shared output infrastructure is stable but cross-platform filesystem behavior is moderately volatile.

## Encapsulated Knowledge

- Output-root containment and whole-plan validation.
- Atomic replacement and exact drift semantics including executable intent.
- Deterministic provenance exclusions.
- Safe direct process execution for optional native checks.

## Public Contract

<!-- contract: BuildPlan, PlannedFile, NativeCheck, Diagnostic — restated from internal/compiler/model/module.md -->

```text
NewWorkspaceLayoutGuard(workspace-root, source-root, output-root) -> WorkspaceLayoutGuard + error
WorkspaceLayoutGuard.Revalidate() -> error
WorkspaceLayoutGuard.RevalidateArchiveDestination(archive-output) -> error
write(WorkspaceLayoutGuard, BuildPlan, output-root) -> [Diagnostic]
compare(WorkspaceLayoutGuard, BuildPlan, output-root) -> [Diagnostic] + Boolean
provenance(BuildPlan, ProvenanceInput) -> BuildPlan + [Diagnostic]
archive(WorkspaceLayoutGuard, DistributionMetadata, BuildPlan, archive-output) -> [ArchivePath] + [Diagnostic]
verify([NativeCheck], output-root) -> NativeVerificationResult
```

`WorkspaceLayoutGuard` is an opaque value that proves source and output roots are
disjoint (not equal, not one inside the other, not symlink/junction aliases). Construct
with `NewWorkspaceLayoutGuard` before source ingestion. Pass to every mutating operation
(`write`, `archive`) and to `compare`. The zero value is rejected by all three operations
with diagnostic code `invalid-workspace-layout`. The guard retains both original aliases
and their construction-time canonical roots. `Revalidate` rejects alias changes and
re-checks physical disjointness at TOCTOU-sensitive boundaries. Archive revalidation
also rejects a destination equal to, inside, or containing source or generated output.
Archive destinations are pinned with a no-follow, descriptor-relative `os.Root`
operation; identity is checked again before temporary creation and final replacement.

`PlannedFile.executable` is semantic data, not an inferred extension or shebang property. On POSIX it means at least one execute bit; false means none. On Windows any true value is rejected before a child artifact operation with `ARTIFACT_EXECUTABLE_INTENT_UNSUPPORTED`. Interpreter-backed scripts remain buildable on Windows when their explicit intent is false.

`write` and `archive` are the mutating operations. `write` skips replacement when the complete output is current; `archive` skips replacement when an archive's bytes are unchanged. `compare` and provenance generation do not write. `verify` is reachable only under `check --native` after exact compare reports no drift. Native output cannot change generated bytes or source.

## Integrations

- **Counterpart**: `internal/compiler`
  - **Direction**: orchestration appends provenance, then selects write or compare, then optional verification.
- **Counterpart**: `internal/compiler/model`
  - **Direction**: validates and consumes model-owned plans/files/checks.
- **Counterpart**: child artifact leaves
  - **Direction**: delegates archive creation, replacement, comparison, provenance, and process execution through their public contracts.

## Internal Design

The parent validates one complete `BuildPlan` before any child operation. Provenance is appended before both build and check. Selected output is staged as a whole. Drift compares path, bytes, executable intent, and allowed file set. Adapter leaves may declare native checks; artifact code does not invent vendor commands.

## Constraints and Invariants

- `write`, `compare`, and `archive` require a valid `WorkspaceLayoutGuard` and reject the zero value with `invalid-workspace-layout`.
- The guard is constructed before source ingestion (Gate 0), re-verified immediately before import, and re-verified at each mutating operation boundary.
- Paths are relative, contained, symlink-free, collision-free after case folding, and valid for supported platforms.
- Native package roots contain only target-native files; `.agentbundler/build.json` is compiler-owned outside them. Archives contain only current target-native roots and exclude compiler and compatibility files.
- Provenance records output executable intent and excludes time, hostname, absolute paths, Git state, installed tools, environment, network results, native checks, and its own hash.
- `check` never writes. Native verification never precedes or replaces exact drift comparison.
- Production native checks are initially limited to `claude plugin validate --strict <root>` and `grok plugin validate <root>`, as declared by those leaves. Codex, Copilot, Cursor, and Pi install/load checks remain test-only and isolated.
- Artifact services do not publish, install, authenticate, fetch, or mutate vendor configuration.

## Test Specification

- Whole-plan validation covers unsafe paths, collisions, symlinks, platform names, and Windows executable rejection.
- Write then compare is current for executable and non-executable POSIX files.
- Missing, changed bytes/mode, and extra paths are distinct deterministic drift.
- Native processes start only after no drift and receive only validated direct argv/working-directory data.
