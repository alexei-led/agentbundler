# Compiler Orchestration

**Path**: `internal/compiler/` — the module's code is everything in this folder and its transparent subfolders, excluding child module folders
**Parent**: repository root
**Submodules**: `model`, `source`, `composition`

`internal/compatibility` is a sibling stage owned outside this module. The compiler orchestrator invokes its public plan/compare/write contract after provenance and before the final mode result.

## Purpose

This module coordinates one deterministic compilation without owning source topology, overlay algorithms, vendor schemas, runtime execution, or artifact effects.

## Functional Responsibilities

- Import one explicit source topology.
- Resolve adapters and compose selected packages for each target.
- Construct one explicit target-neutral `TargetRenderInput` per target.
- Assemble target plans, provenance input, and one complete build plan.
- Route the plan to write, compare, and optional native verification in legal order.

## Subdomain Classification

**Core.** The workflow is small but changes with shared source/render policy.

## Encapsulated Knowledge

- The only legal sequence: **Gate 0 layout guard**, import, compose, render, provenance, write/compare, optional verify.
- Gate 0 constructs `artifact.WorkspaceLayoutGuard` from manifest source and output roots before any filesystem read or write. Equal, containing, or symlink-aliased source/output pairs are rejected with `invalid-workspace-layout`. The original aliases are revalidated immediately before source import.
- Selector defaulting and target-wide render-request construction.
- The difference between pure build-plan generation and artifact effects.

## Public Contract

<!-- contract: SourceManifest, TargetID, PackageID, TargetRenderInput, BuildPlan, Diagnostic — restated from internal/compiler/model/module.md -->

```text
BuildMode = build | check
CompileRequest = { workspaceRoot: absolute cleaned directory path, manifest: SourceManifest, targets: [TargetID], packages: [PackageID], mode: BuildMode, nativeVerify: Boolean }
CompilationResult = { plan: BuildPlan, diagnostics: [Diagnostic], drift: Boolean, nativeVerificationFailed: Boolean }
compile(CompileRequest) -> CompilationResult
```

For each selected target, the compiler passes the adapter an explicit `TargetRenderInput` containing ordered normalized packages, common distribution metadata, explicit `separate` or `aggregate` mode, and explicit aggregate identity/metadata when applicable. When `distribution.version` is present, it is the generated version for every package and aggregate manifest; source package versions remain import evidence, not competing output ownership. The compiler never infers aggregate mode from package count or takes distribution metadata from an arbitrary package.

### Go API

**Package**: `github.com/alexei-led/agentbundler/internal/compiler`

`Compile` validates the workspace root and request before collaborators run. No selector means manifest targets and all selected packages. `nativeVerify` is valid only for check. Error diagnostics prevent dependent rendering and artifact action.

## Integrations

- **Counterpart**: `internal/compiler/source`
  - **Direction**: imports `SourceInventory` from the manifest and workspace root.
- **Counterpart**: `internal/compiler/composition`
  - **Direction**: composes each selected target into ordered normalized packages.
- **Counterpart**: `internal/target`
  - **Direction**: resolves adapters/capabilities and calls `render(Adapter, TargetRenderInput)`.
- **Counterpart**: `internal/artifact`
  - **Direction**: appends provenance, writes or compares, archives through the facade, then optionally verifies declared native checks.
- **Counterpart**: `internal/compatibility`
  - **Direction**: prepares repository-root compatibility from the canonical plan, then writes or compares it alongside target output.
  - **Shared knowledge**: compatibility configuration, output path, canonical `BuildPlan`, and compatibility plan only.
- **Counterpart**: `internal/compiler/model`
  - **Direction**: constructs and validates shared model values.

## Internal Design

The compiler reads no asset directly. Only this orchestrator combines manifest distribution/package-mode declarations with composed packages. Adapters remain pure and receive no filesystem root. Native checks are executed only after an exact successful comparison and cannot change generated bytes.

## Change Vectors

- Add a shared compilation stage with more than one source/target consumer.
- Change selector or target-wide distribution behavior.
- Add a plan-based artifact action.

## Constraints and Invariants

- Imports only public facades of model, source, composition, target, artifact, and compatibility.
- Never imports vendor leaves, importer leaves, serializers, filesystem, process, network, clock, Git, or environment output inputs.
- `separate` remains the version-1 default. `aggregate` is explicit and valid only for Pi package profile with aggregate identity/metadata.
- Build and check use the same imported, composed, rendered, provenance-augmented plan.
- No package/catalog publication, installation, credentials, or vendor configuration mutation exists.
- Generated bytes depend only on source/manifest values, adapter revision, and embedded runtime bytes.

## Test Specification

- Collaborator calls occur in fixed order and errors short-circuit dependent work.
- Existing hook-free manifests construct separate render inputs unchanged.
- Pi aggregate input is explicit; non-Pi aggregate input fails before render.
- Build and check produce identical plans; native verification runs only after current output.
